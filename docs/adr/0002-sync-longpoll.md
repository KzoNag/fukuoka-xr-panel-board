# ADR 0002: 画面同期は SSE ではなくロングポーリング

日付: 2026-09-18

## 状況

参加者・ボード・進行役の3画面を同じ状態に保つ必要がある。最初は
Server-Sent Events(`GET /api/events`)で実装し、localhost では問題なく動いた。

## 問題

cloudflared クイックトンネル経由だと SSE の本文が届かなかった
(ヘッダは 200 で返るが 8 秒待っても 0 バイト。`--protocol quic` / `http2` の両方、
`content-type: text/event-stream` 厳密指定、4KB のコメント先行送信でも変わらず)。
エッジかトンネルのどこかでレスポンスをバッファしていると思われ、
当日会場のネットワークで切り分けする余裕はない。

## 検討した選択肢

1. **SSE を直す**: 原因が cloudflared 側にあり、こちらで制御できない。却下
2. **WebSocket**: cloudflared は WebSocket を正式サポート。ただし依存なしで
   ハンドシェイクとフレーミングを自前実装する必要があり、前日に増やすリスクとしては大きい
3. **短間隔ポーリング(2秒)**: 確実だが最大2秒遅れ、15端末で常時 8 req/s
4. **ロングポーリング**(採用): `GET /api/state?since=<version>` を変化があるまで
   最大25秒保留する。完了したレスポンスは普通に返るので、どんなプロキシでも通る。
   通知は即時、待機中はリクエスト数ほぼゼロ

## 決定

4 を採用。`version` はサーバー起動時の `Date.now()` から単調増加させ、
再起動をまたいでもクライアントの `since` が未来にならないようにした。
クライアントは失敗時に 1〜5 秒のバックオフで再試行し、40 秒で fetch を打ち切る
(Cloudflare の 100 秒アイドル制限より十分短い)。

SSE のコードは削除した。1つの同期経路だけにして当日の切り分けを単純にするため。
